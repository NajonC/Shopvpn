## Interfaces

Routine API choices for this library:
- Frozen dataclass `AuditEvent(event_id: str, occurred_at: int, actor_domain: str, actor_id: str, action: str, resource_kind: str, resource_id: str, reason: str | None = None, evidence_ref: str | None = None)`.
- `AuditWriteError(Exception)`: explicit sanitized database-write failure. Do not expose SQL parameters, backend error text or its formatted exception chain; wrap sqlite3 errors with a constant message and `from None`. Never claim write success after failure.
- `sanitized_diagnostic(*, operation: str, tenant_id: int, record_id: int, error: BaseException | None = None) -> dict`: exactly operation/tenant_id/record_id. Ignore error without stringifying it. No outcome/success fields.
- `write_audit_event(conn: sqlite3.Connection, event: AuditEvent, *, diagnostic: Mapping | None = None) -> str`: a single parameter-bound INSERT into `composite_audit_events`, returning event.event_id only after execute succeeds. Use all ten schema columns in order: event_id, occurred_at, actor_domain, actor_id, action, resource_kind, resource_id, reason, evidence_ref, diagnostics. No UPDATE/DELETE/REPLACE/ignore-on-conflict, upsert, commit, rollback, BEGIN, connections or schema changes.
- `diagnostic=None` stores SQL NULL. Otherwise rebuild a dictionary containing only `operation`, `tenant_id`, `record_id` from the supplied trusted structured mapping, then JSON-encode that dictionary; discard extras including error/token/completed. Do not mutate input.
- Actor domains are schema-defined `telegram`, `web_admin`, `payment_callback`, `system`, `cli`. Rely on real SQLite constraints for invalid values; no authority decisions in this storage utility. All five valid domains remain allowed.
- Event metadata and the three diagnostic identifiers are trusted, already-authorized structured inputs. Private reason/evidence text persists exactly (including quotes), is never logged, and must not be reused for public output. Do not attempt heuristic secret detection in these fields; callers must not supply credentials as metadata. Document this boundary. Arbitrary error payloads are never stored.
- Caller owns atomic transaction/commit/rollback through the repository. Database errors propagate as AuditWriteError; transaction remains caller-owned. No key generation, token handling, retries or remote effects here.
