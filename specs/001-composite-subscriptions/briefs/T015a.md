## Goal

The tests in this packet characterize existing code: they pin what happens today when staff press "approve" on a pending order in the Telegram admin bot (`cb_order_approve`), unsafe parts included, so later tasks that change approval can show exactly what changed. Approval has four branches (stock allocation, direct panel provisioning, custom config, renewal); each claims the order, does its remote or local step, approves, logs, then delivers. You write no production code; every test must pass against today's code. The packet also adds `caption`/`edit_caption` to the harness `FakeMessage`, because the real admin message is a receipt photo.
