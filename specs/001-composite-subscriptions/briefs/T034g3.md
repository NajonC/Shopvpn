**Schema design (Claude's; T040 builds exactly this).** Times are epoch ms. "Never changes" and "kept" refusals are triggers.

`composite_recovery_cases`, primary key `case_id`:
- Required, never change: `installation_id`, `scope_ref`, `restored_point_id`, `pre_restore_set_ref`, `restrictions` (non-empty text); `scope_kind` (`record`, `customer`, `campaign`, `money`, `panel`); `old_restore_epoch` (integer ≥ 0: the restore epoch the restored point was captured in); `new_restore_epoch` (integer > `old_restore_epoch`: the epoch this restore started); `restored_captured_at`; `restored_manifest_sha256` (32-byte blob); `opened_at` (≥ `restored_captured_at`). The restored point is stored by value, with no foreign key: the restored file's recovery-point table predates that point.
- Unique `(new_restore_epoch, scope_kind, scope_ref)`: one case per scope per restore.
- Release: `released_at`, `release_kind` (`verified`, `usage_settlement`, `governed_remediation`) and `release_audit_event_id` (foreign key to `composite_audit_events`) are all NULL or all set. `follow_up_due_at` is set exactly when the kind is `governed_remediation`, and is > `released_at`.
- Insert: a case opens held, with every release column NULL. Update: the identity columns never change; a released case never changes again. Releasing needs at least one fact and no `unknown` fact; `verified` needs every fact `verified`; `usage_settlement` needs an `irrecoverable` fact and every `irrecoverable` fact of kind `usage`; `governed_remediation` needs an `irrecoverable` fact of a kind other than `usage`. When the release event exists it must have `resource_kind = 'composite_recovery_cases'`, `resource_id` = the case, a non-NULL `reason` and `occurred_at ≤ released_at`, with no fact of the case resolved after `occurred_at` (facts are recorded after the case opens, so a decision taken before then is refused too); for `governed_remediation` its `actor_domain` is not `system` or `payment_callback` and its `evidence_ref` is set. A missing event is left to the foreign key. Rows are never deleted.

`composite_recovery_evidence`, primary key `evidence_id`:
- Required, never change: `case_id` (foreign key); `fact_kind` (`ownership`, `purchase`, `financial`, `lifecycle`, `token`, `remote_identity`, `usage`, `coupon`, `test_claim`, `campaign`, `cleanup`); `subject_ref`, `fact` (non-empty text); `recorded_at`. Optional, never changes: `source_ref` (non-empty when set: the preserved pre-restore or newer reference the fact came from).
- `status`: `unknown` (default), `verified`, `irrecoverable`. `resolution_ref` (non-empty) and `resolved_at` are set exactly when the status is not `unknown`; `resolved_at` ≥ `recorded_at`.
- Insert: the case is held and `recorded_at ≥` its `opened_at` (a missing case is left to the foreign key). Update: a resolved fact never changes. Rows are never deleted.

`composite_subscriptions.recovery_hold_case` (an existing column, no foreign key): inserting a non-NULL value, or changing the column to a non-NULL value, needs that case to exist and be held; changing it to NULL needs the old case released. An update that leaves the value as it was is not checked.
