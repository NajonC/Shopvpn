## Goal

Add `tests/_harness/secret_scan.py`, which later tests use to prove that no secret leaks. A test registers the secrets it generated (subscription tokens, client UUIDs, Trojan passwords, panel tokens, payment keys), then checks captured logs, exception text, HTTP responses given to unauthorized callers, and files. The check fails if any registered value appears, written out or inside base64, or if any subscription URL appears. The failure report names the kind of secret, a fingerprint and the place. It never contains the value itself.

## Rules

1. Task [tasks.md T012]: "It fails when generated tokens, UUIDs, Trojan passwords, panel tokens, subscription URLs or payment keys appear in captured logs, exception text, HTTP bodies returned to unauthorized callers, or fixture files". [spec FR-084]: "Panel/subscription secrets and authentication payloads MUST be excluded from source control, general logs, unauthorized responses and fixtures". [contracts/subscription-http.md]: "`GET /sub/{token}` accepts an opaque 256-bit random base64url token (43 unpadded characters)"; "Proxy/app/metrics redact full token-bearing path and body".
2. **Never reveal a value.** A finding, a message or a `repr` shows only the kind and `fingerprint(value)`, which is `hashlib.sha256(value.encode("utf-8", "surrogateescape")).hexdigest()[:12]`. The module never logs or prints. Every public `check_*` method sets `__tracebackhide__ = True`. Say this in the module docstring, together with rule 1.
3. **Registry.** `add(kind, value)` stores a secret.
   - `kind` must be a `str` (`TypeError`) and not `""` (`ValueError`).
   - `value` must be a `str` (`TypeError`) of at least 16 characters (`ValueError`).
   - A failed call stores nothing. Adding a value that is already stored changes nothing, so it keeps its first kind.
   - `registered` is a read-only tuple of `(kind, fingerprint)` pairs in the order the values were first added.
   - `repr(scan)` is `SecretScan(registered=<count>)`.
4. **Helpers.**
   - `add_fixture(fixture)` adds, in this order:
     - each panel's `api_token` as `"panel token"`;
     - each inbound's non-empty `reality_private_key` as `"REALITY private key"`;
     - then for each subscription its `url_token` as `"subscription token"`, followed by each credential in order, as `"client UUID"` when `secret_kind == "uuid"` and as `"Trojan password"` otherwise.
   - `add_panel(panel)` adds every value of `panel.tokens`, in dict order, as `"panel token"`.
   - `add_payment_method(method)` adds `method.api_key` as `"payment key"`.
5. **Text and decoding.** `find(text, *, source)` accepts `str`, or `bytes` decoded with `decode("utf-8", "surrogateescape")`; anything else is a `TypeError`. `source` must be a `str` (`TypeError`) and not `""` (`ValueError`). Depth 0 is the text itself. Depths 1, 2 and 3 are the base64 decodings of every text at the previous depth. To decode a text:
   1. Take every match of `[A-Za-z0-9+/_-]{16,}`.
   2. For each match and each start offset 0, 1, 2 and 3, take the match from that offset. If its length divided by 4 leaves 1, drop the last character.
   3. Replace `-` with `+` and `_` with `/`, pad with `=` to a multiple of 4, and decode with `base64.b64decode(..., validate=True)`.
   4. Turn the bytes into a new text with `decode("utf-8", "surrogateescape")`.
6. **Matching.** A registered value is found at a depth when some text at that depth contains it.
   - A value that fully matches `[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}` (a UUID) also matches in any letter case and with its hyphens removed. Every other value matches only exactly, case-sensitive.
   - Independently, every match of `(?:/|%2[Ff])sub(?:/|%2[Ff])([A-Za-z0-9_-]{43})(?![A-Za-z0-9_-])` at any depth is a finding of kind `"subscription URL"` for the captured token, unless that token is a registered value.
   - Each value or token is reported at most once per `find` call, at the lowest depth where it occurs.
   - Order: registered values in registration order, then subscription-URL findings sorted by fingerprint.
7. **Findings.** `find` returns a tuple of `SecretFinding(kind, fingerprint, source, decodings)`, where `decodings` is the depth. Each `check_*` method gathers the `find` results of its parts, in the order given below. If there are none it returns `None`; otherwise it raises one `SecretLeak` with all of them.
   - `SecretLeak` subclasses `AssertionError` and has a `findings` attribute.
   - Its `str()` is `"secrets found:"` followed by one line per finding: `"<kind> <fingerprint> in <source>"`, with `", base64 depth <n>"` appended when `n > 0`. Lines are joined with `"\n"`.
8. **The check methods.**
   - `check_text(text, *, source)` is `find` plus raising.
   - `check_logs(records)`:
     - Each item must be a `logging.LogRecord` (`TypeError`). Item `i`, counting from 0, has source `f"log record {i} ({record.name})"`.
     - Its text joins with `"\n"`: `record.getMessage()` (left out if it raises any `Exception`); `"".join(traceback.format_exception(record.exc_info[1]))` when `record.exc_info` is a tuple whose second item is not `None`; and `repr(v)` for every value in `vars(record)`.
   - `check_exception(exc)`:
     - `exc` must be a `BaseException` (`TypeError`). Source is `f"exception {type(exc).__name__}"`.
     - Text joins with `"\n"`: `str(exc)` (left out if it raises any `Exception`), `repr(exc)`, and `"".join(traceback.format_exception(exc))`. That last part covers causes, notes and groups.
   - `check_http(body, *, headers=None, source="HTTP response")`:
     - `source` is validated as in `find`. The body (`str` or `bytes`) has source `f"{source} body"`.
     - `headers` is `None`, an object with `.items()` (a dict, or aiohttp's `CIMultiDict`, which repeats names), or an iterable of `(name, value)` pairs. Names and values are `str` or `bytes` (anything else is a `TypeError`), and `bytes` are decoded as in rule 5.
     - Each header is scanned as `f"{name}: {value}"` with source `f"{source} header {name}"`, in order.
   - `check_files(*paths)`:
     - Each path, in argument order, must exist (`FileNotFoundError`) and must not be a symlink (`ValueError`).
     - A file is one entry whose name is `path.name`. A directory gives every file and directory below it as entries, except symlinks, which are never read or followed. Each entry's name is its path relative to the directory in POSIX form, and entries are sorted by that name.
     - For each entry: scan its name with source `f"file name {full_path}"`. If it is a regular file, also scan its bytes with source `f"file {full_path}"`. Here `full_path` is the given path joined with the relative name, and is the given path itself for a file.
