## Goal

The tests in this packet characterize existing code: they pin what happens today when a buyer sends a payment receipt (photo or document) for a pending order, unsafe parts included, so the later task that changes these paths can show exactly what changed. There are two paths: the FSM path, when the buyer's state is still `BuyFlow:waiting_receipt`, and the fallback, when the state was lost. You write no production code; every test must pass against today's code. The packet also adds three small things to the T013 harness so a receipt message can be routed through the real router.
