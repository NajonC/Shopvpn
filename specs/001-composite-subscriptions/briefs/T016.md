## Goal

The tests in this packet characterize existing code: they pin what the wallet and order helpers in `database.py` do today, unsafe parts included, so the later tasks that make these effects atomic can show exactly what changed. The core finding to pin is that a refund or credit is a separate commit after the status change, so a real process crash between them loses the money for good. You write no production code; every test must pass against today's code.
