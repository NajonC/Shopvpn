## What already exists

- `handlers_user.py` (do not change):
  - `class _MessageCall` (lines 100–110): wraps a text message as a callback; its `answer(text=None)` sends only when `text` is truthy.
  - `create_user_router(db, is_main_bot: bool = True, bot_manager=None) -> Router` (line 113). Handlers are nested functions registered on the returned router:
    - `router.callback_query`: `cb_buy_start(call, state, bot)` (lines 1033–1036, data `"buy_start:<product_id>:<quantity>"`) calls `_buy_start(call, state, bot, product_id, quantity, config_name=None)` (lines 1038–1253); `cb_buy_random_config_name(call, state, bot)` (lines 1255–1263) calls `_buy_start(..., config_name="")` with the product and quantity saved in FSM data.
    - `router.message`: `buy_receive_config_name(message, state, bot)` (lines 1265–1286) validates the typed name, answers `"⏳ در حال ثبت سفارش..."`, and calls `_buy_start(_MessageCall(message.from_user, progress), ..., config_name=<name>)` where `progress` is the message that answer returned.
  - `_buy_start` reads stock, then FSM `discount_code_id`/`discount_amount`, product payment methods, tier price; debits the wallet (`db.add_wallet_credit(user, -wallet_used)`), increments the coupon (`db.increment_discount_usage`), inserts the order (`db.create_order`), each a separate call. If `final_price <= 0` it clears FSM and fulfils at once (stock `db.take_unused_configs` + `db.approve_order`; product with `provision_server_id` → `provision_direct`; auto product without server → `provision_auto_config`; then `db.approve_order_auto`), runs `check_and_notify_low_stock` (stock only), `db.reward_referrer_if_first_purchase(user, order["base_price"])`, notifies admins, edits `call.message`, then `deliver_config_to_user(bot, call.from_user.id, ...)`. Otherwise it shows the payment keyboard and sets state `BuyFlow:waiting_receipt`. An `Exception` after the order insert is logged on logger `"handlers_user"` with args `(order_id, user_id)`, the order is rejected (`db.reject_order` refunds wallet and coupon only while the order is still `pending`) and a generic error is shown.
  - Module globals it calls by name, so `monkeypatch.setattr(handlers_user, ...)` replaces them: `provision_direct`, `provision_auto_config`, `DirectProvisionError`.
