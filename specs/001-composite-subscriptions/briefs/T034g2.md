## Rules

1. "**`composite_recovery_points`**: coherent capture ID/time, schema/release/runtime inventory, manifest members/checksums/FSM dependencies, validation results, separately encrypted archive reference, verified off-host availability/destination identity, last verified capture age/overdue. Persistent delivery attempts record B-01 policy version, immutable capture/hash/destination, unique attempt paths, dispatch/count/next-attempt/budget, partial/uncertain outcome, completion verification and recovery audit … Do not reset capture age on transfer/validation or treat incomplete set as protected." [data-model §11] "FKs use RESTRICT for protected dependencies; no cascade deleting financial/history/cleanup." "absolute times use UTC epoch milliseconds" [data-model, storage rules]
2. "At most three automatic delivery/reconciliation attempts for a capture, waiting 15 then 45 seconds after retryable failure. … Overall automatic deadline is capture time + 600 seconds …; if a prior valid off-host point is still within its age objective when this capture starts, also cap it at that point's capture time + 900 seconds. Persist that deadline for this capture. A genuinely new scheduled capture starting after protection is already overdue uses capture+600 seconds … At deadline record exhaustion/missed protection even if a transfer remains uncertain." [contracts/operations.md B-01, Attempts/backoff/budget]
3. "Verified pre-upload connection rejection/no-write failure is retryable only for a transient cause. Host-key mismatch, invalid credentials/permissions, manifest/checksum mismatch or exhausted destination space stops automatic attempts and exposes the exact repair need. Partial files are never recoverable points." "Use unique immutable capture-and-attempt paths … another bounded attempt uses a distinct path" [B-01, Definitive failure; Partial/uncertain outcomes]
4. "Verify remote closed archive size and whole-file checksum against the locally validated encrypted archive and manifest, and verify the completion manifest binds the same members, capture ID/time and hashes. … file existence/size or successful SFTP return alone is insufficient. Only immutable, fully verified sets enter the recovery-point inventory; a renamed file with a possibly live writer remains uncertain even if its current checksum matches." "Require close/drain or immutability evidence excluding further changes as well as integrity verification before counting success." [B-01, Completion evidence; Partial/uncertain outcomes]
5. "Persist capture/hash/destination identity, policy version, attempts/paths/dispatch, partial/uncertain state, next attempt, original budget and verified completion evidence. Restart … does not assume success or grant fresh attempts. Retain the last valid recoverable copy until a newer capture is independently verified; no failed/late upload deletes or demotes it." [B-01, Restart and preservation]
6. "Owner web shows last verified capture time/age, missed age target, pending/uncertain paths, exhausted attempt count and repair action … Audited later recovery of an old capture may use three attempts with the same per-call/backoffs and a 420-second recovery-window limit; keep the original exhausted budget/miss and immutable capture time." **Schema design (Claude's; T040 builds exactly this).** Times are epoch ms. "Never changes" and "kept" refusals are triggers.

`composite_recovery_points`, primary key `recovery_point_id` (the capture ID):
- Required, never change: `installation_id`, `release`, `runtime_inventory`, `manifest` (members, checksums, FSM dependencies), `archive_ref`, `encryption_key_id`, `validation_report`, `destination_id`, `policy_version` (non-empty text); `restore_epoch` (integer ≥ 0); `schema_version` (integer ≥ 1); `captured_at`; `validated_at` (≥ `captured_at`); `manifest_sha256`, `archive_sha256` (32-byte blobs); `archive_bytes` (integer > 0); `delivery_deadline`. Optional, never changes: `predecessor_point_id` (foreign key to this table).
- `delivery_state`: `delivering` (default), `verified`, `exhausted`, `stopped`; `delivery_closed_at` is set exactly when the state is not `delivering`, and ≥ `validated_at`.
- `verified_at` and `verified_attempt_id` are set together; foreign key `(verified_attempt_id, recovery_point_id)` to the attempts' `(attempt_id, recovery_point_id)`. A verified point is not `delivering`; a `verified` point has `verified_at`.
- `age_target_missed_at` needs `verified_at`, and is ≥ `verified_at` and ≥ `captured_at + 900000`.
- Insert: the row starts `delivering`, unverified and not missed. The predecessor is the newest point verified at or before `captured_at`: it is required when such a point exists, and must be verified by `captured_at` with no point captured after it verified by then. `delivery_deadline` = min(`captured_at + 600000`, predecessor's `captured_at + 900000`) when the predecessor's `captured_at + 900000 > captured_at`, else `captured_at + 600000`.
- Update: the state leaves `delivering` once, then it and `delivery_closed_at` never change; closing needs no unfinished attempt. `exhausted` needs no verified attempt, and either `delivery_closed_at ≥ delivery_deadline` or an automatic attempt number 3. `stopped` needs no verified attempt and an automatic attempt finished `rejected`. `verified` needs `verified_attempt_id` to be an automatic attempt. Setting `verified_at` needs `verified_attempt_id` to be this point's attempt, finished `verified` at or before `verified_at`, and the state `verified` exactly when that attempt is automatic (a recovery attempt verifies an `exhausted`/`stopped` point without changing its state). `verified_at`, `verified_attempt_id` and `age_target_missed_at` are set once and never change. `age_target_missed_at` is refused when a point captured later was verified at or before it. Rows are never deleted.

`composite_recovery_delivery_attempts`, primary key `attempt_id`, unique `(attempt_id, recovery_point_id)`:
- `recovery_point_id` (required, foreign key); `allowance` (`automatic` or `recovery`); `audit_event_id` (foreign key to `composite_audit_events`, set exactly for `recovery`); `attempt_number` (1–3); `remote_path` (required, non-empty, unique over the table); `reserved_at` (required). Unique `(recovery_point_id, attempt_number)` for automatic attempts, `(audit_event_id, attempt_number)` for recovery attempts, and one unfinished attempt per point: unique `recovery_point_id` where `outcome IS NULL`.
- `dispatched_at` NULL or ≥ `reserved_at`. `finished_at` and `outcome` set together; `finished_at` ≥ `reserved_at` and ≥ `dispatched_at`. `outcome`: `no_write` (verified nothing written, transient), `rejected` (definitive), `partial`, `uncertain`, `verified`; all but `no_write` need `dispatched_at`. `failure_kind` (`host_key_mismatch`, `credentials`, `checksum_mismatch`, `destination_space`) set exactly when `rejected`. `next_attempt_at` = `finished_at + 15000` (number 1) or `+ 45000` (number 2) when the outcome is `no_write`, `partial` or `uncertain` and the number is below 3; NULL otherwise. `readback_bytes`, `readback_sha256`, `completion_manifest_ref`, `closure_evidence_ref` are all set when `verified` and all NULL otherwise; finishing `verified` needs the read-back equal to the point's `archive_bytes` and `archive_sha256`.
- Insert (a reservation before any network work): every column from `dispatched_at` on is NULL. Automatic: the point is `delivering` and `validated_at ≤ reserved_at < delivery_deadline`. Recovery: the point is `exhausted` or `stopped` and unverified, and the audit event has `resource_kind = 'composite_recovery_points'`, `resource_id` = the point, and `occurred_at ≤ reserved_at < occurred_at + 420000`. Number n > 1 needs number n − 1 of the same point, allowance and audit event, with `next_attempt_at ≤ reserved_at`.
- Update: the identity columns (`attempt_id`, `recovery_point_id`, `allowance`, `audit_event_id`, `attempt_number`, `remote_path`, `reserved_at`) never change; `dispatched_at` is set at most once; a finished attempt never changes. Rows are never deleted.
