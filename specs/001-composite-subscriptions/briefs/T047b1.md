## Interfaces

Routine adapter API for T048:
- `web_principal(admin, *, main_installation_id: str, main_owner_web_admin_id: int) -> Principal`.
- `admin` must come from `get_current_admin`, not request JSON. Its `tenant` must be exactly the established main slug `""`, role `owner`, positive integer web ID equal to the explicitly supplied trusted main-owner web ID, and it must have no `mobile_token_id` key. No type coercion from strings/bools or fallback to configured Telegram OWNER_ID.
- Mapping and installation arguments are trusted server configuration/identity bindings, never request fields. No deployment ID is selected here. T048/T049 must wire that binding from authorized configuration, fail closed when absent, and must not infer it from a matching Telegram number. The specific configuration storage is outside this packet.
- Success preserves the authenticated web ID and trusted installation: `Principal("web_admin", admin["id"], main_installation_id, "owner", "web")`. No hardcoded actor or installation. Authenticated row role wins over stale signed cookie claims.
- Invalid mappings/authority raise existing planned `AuthorityError("forbidden")`, with `.code == str(error) == "forbidden"`. Existing unauthenticated sessions fail upstream with HTTP 401; no effect or principal is created.
- This adapter does not authorize arbitrary Python objects, business commands or customer resource access. The inherited Telegram ownership guard must still refuse a web principal with an equal numeric customer ID.

## Tests

Orchestrator-written. A synthetic main DB has mapped web owner 1, unmapped owner 2, orders-only staff 3 and admin staff 4. Telegram owner 2 deliberately overlaps the unmapped web owner. A tenant DB also has owner 1. All cookies use the independent harness signer.

- `test_web_explicit_owner_mapping_preserves_web_domain_and_configured_identity` (2): main owner 1/MAIN and explicitly mapped owner 2/second installation both allowed, despite stale signed support role and conflicting request selectors/body. Exact five principal fields, exactly one own sink increment and zero other increments.
- `test_web_database_staff_role_cannot_be_replaced_by_signed_owner_claim` (2): orders staff/admin, valid signed owner claim and matching trusted mapping; forbidden and unchanged sink. Only role is invalid.
- `test_web_signed_tenant_cannot_be_replaced_by_main_selector` (2): matching owner ID/role in signed tenant, forged main request selectors; ordinary/full-access reseller both forbidden, unchanged sink.
- `test_web_telegram_owner_number_does_not_authorize_unmapped_web_owner`: web ID == Telegram OWNER_ID == 2, trusted web binding 1; forbidden, unchanged sink.
- `test_web_mapping_must_be_explicit_valid_web_id` (4): None, 0, string "1", bool True forbidden.
- `test_web_adapter_refuses_incomplete_or_wrong_authentication_domain` (7): None/"main"/foreign tenant, bool/string/None actor or mobile_token_id; independently invalidate one field with other conditions valid; forbidden/no effect.
- `test_web_valid_identity_never_becomes_customer_authority_on_equal_numbers`: valid web principal cannot pass customer guard even when persisted customer ID is 1.
- `test_web_invalid_session_never_reaches_principal_or_effect` (3): tampered HMAC, expired cookie, inactive authenticated DB account; real authenticator raises 401 before principal/effect.
