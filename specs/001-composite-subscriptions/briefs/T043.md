## Rules

1. “Never encode everything into one mutable `enabled` flag.” “Common expiry continues while inactive.” [data-model §3]
2. “A fulfilled service in `cancel_pending` with an authorized renewal still uses its existing entitlement and restrictions: pending cancellation alone neither disables access nor invalidates its current URL.” [data-model §3]
3. “Exhaustion at or above the exact purchased byte threshold or common expiry MUST trigger all-child remote restriction” [spec FR-037; this packet computes intent only]
4. “Publication separately requires verified ownership/token/complete generation and no initial-delivery, replacement or recovery publication block; owner suspension is status-only, while ordinary expiry/exhaustion/customer/reporting disable retains the complete current list.” [data-model §3]
5. “Partial results do not create confirmed complete readiness.” [data-model §5]
6. “A request carrying the same desired state cannot undo it, nor can an access-reducing request undo `confirmed_fresh_auth_denied` (RX-D8).” [data-model §3] “Any other uncertain request still blocks confirmation until its quarantine ends, for example an enable while access is being denied.” [research RX-D8]
7. Owner decisions, verbatim [2026-11-05, resolving T042 open points in order]: “On, unless a restriction applies; off if cancelled during setup”; “Leak replacement: delivery only. First delivery blocked: access off. No published configuration needed”; “partial”; “a) 503, b) 404, c) 503”; “Not expired”. For decision 4, (a) means candidate token, (b) failed_unfulfilled, (c) owner suspension combined with a gate-2 condition.

The following precise rules implement those decisions and the accepted T042 interface:

8. `desired_access`: allow `preparing`, `fulfilled`, or `cancel_pending` with `authorized_renewal`; deny cancelled/failed initial/initial-provisioning cancellation. In every allowed phase deny expired/exhausted, customer/owner/reporting restriction, a non-None recovery hold, initial delivery block, or non-None final cancellation time. Replacement delivery block and published-generation presence do not restrict access. Availability time is informational, not an additional prerequisite. This is desired convergence of verified caller-supplied facts, not permission to adopt an unverified remote identity or to issue a customer resume command.
9. `publication` precedence: revoked/superseded token, cancelled/failed_unfulfilled lifecycle, or non-None final cancellation time → NOT_FOUND (404); candidate token → UNAVAILABLE (503); preparing, initial-provisioning cancellation, any initial/replacement delivery block or non-None recovery hold → UNAVAILABLE; otherwise owner suspension → STATUS_ONLY (200), even without a published generation; otherwise previously fulfilled (fulfilled or authorized-renewal cancel_pending) with published generation → COMPLETE_LIST (200); otherwise UNAVAILABLE. Never gate publication on expiry, usage, customer disable or reporting suspension. Unknown/malformed tokens are rejected by the future HTTP adapter; this interface accepts TokenStatus only.
10. `confirmed_access`: count matching read-backs strictly after latest_write_at. No qualifying attachment (including empty tuple) → UNKNOWN; some but not all → PARTIAL. All qualifying but required runtime evidence missing, or any undoing request with `now < quarantine_until` → PARTIAL. Otherwise enabled → CONFIRMED_ELIGIBLE, disabled/removed → CONFIRMED_FRESH_AUTH_DENIED. A request is harmless if it carries the same desired state or both desired/carried states are disabled/removed. Quarantine ends exactly at its endpoint. Epoch 0 is a real timestamp, not absence.

## Interfaces

All timestamps are UTC epoch milliseconds (`int`); optional dates are `int | None`. Byte counts are exact integers. Input facts are validated upstream; no new normalization framework or persistence validation.

- `enum.StrEnum` classes; member names are uppercase stored values, in this order:
  - Lifecycle: preparing, fulfilled, cancel_pending, cancelled, failed_unfulfilled.
  - CancelWaitKind: authorized_renewal, initial_provisioning (absence is None).
  - ConfirmedAccess: unknown, partial, confirmed_eligible, confirmed_fresh_auth_denied.
  - TokenStatus: candidate, current, revoked, superseded.
  - GenerationState: preparing, complete_verified, published, retired, blocked_uncertain.
  - RemoteWorkStatus: queued, dispatched, uncertain, confirmed, manual_hold.
  - SweepOutcome: consistent, diverged, unknown.
  - ChildDesiredState: enabled, disabled, removed.
  - Publication: NOT_FOUND, UNAVAILABLE, STATUS_ONLY, COMPLETE_LIST (members in that order; lowercase string values).
- Frozen dataclasses, fields in this exact order (no defaults required):
  - `SubscriptionAccessFacts(lifecycle: Lifecycle, available_at: int | None, expires_at: int | None, allowance_bytes: int, used_bytes: int, customer_disabled: bool, owner_suspended: bool, reporting_suspended: bool, recovery_hold_case: str | None, replacement_delivery_block: bool, initial_delivery_block: bool, cancel_accepted_at: int | None, cancel_wait_kind: CancelWaitKind | None, cancel_final_started_at: int | None, has_published_generation: bool)`.
  - `AttachmentReadBack(observed_at: int, matches: bool)`.
  - `UncertainRequest(carries: ChildDesiredState, quarantine_until: int)`.
  - `ChildAccessEvidence(desired: ChildDesiredState, latest_write_at: int, read_backs: tuple[AttachmentReadBack | None, ...], runtime_required: bool, runtime_evidence: bool, uncertain_requests: tuple[UncertainRequest, ...])`.
- `is_expired(facts: SubscriptionAccessFacts, now: int) -> bool`: False if expires_at is None, else now >= expires_at.
- `is_exhausted(facts: SubscriptionAccessFacts) -> bool`: used_bytes >= allowance_bytes.
- `desired_access(facts: SubscriptionAccessFacts, now: int) -> bool`.
- `publication(facts: SubscriptionAccessFacts, token_status: TokenStatus) -> Publication` (no clock input).
- `confirmed_access(evidence: ChildAccessEvidence, now: int) -> ConfirmedAccess`.

Predicates are pure: no implicit clock, I/O, mutation, imports of configuration, database or services.
