## Interfaces

Routine test seam for T049: `admin_panel.server.create_composite_router(*, main_installation_id, main_owner_web_admin_id, public_origin) -> APIRouter`, prefix `/api/composite`. T049 must use this same factory when mounting its production scaffold. T047b2 mounts its result in a fresh FastAPI app and adds two test-only read/write witnesses, with no endpoint-level dependencies. All authorization must be inherited from the router. It never mounts test endpoints in the real app.

Trusted arguments come from server configuration, never JSON/query/header selectors. Explicit main-owner mapping follows T047b1's contract. No new product authority is granted. Real `get_current_admin`, `require_owner`, `require_main_tenant` and `service.web_principal` run; no auth dependency overrides.

Protocol choice for the new (not yet public) interface: unsafe cookie methods POST/PUT/PATCH/DELETE require BOTH a canonical Origin exactly equal to configured `public_origin` and `X-Composite-CSRF` equal to lowercase HMAC-SHA256 hex using ADMIN_PANEL_SECRET over `b"composite-csrf-v1\0" + session_cookie.encode()`. Read-only GET requires authentication but no CSRF/Origin. Trusted public origin avoids host/forwarded-header reflection. Missing Origin has no Referer fallback. Session-bound token generation/delivery in the owner UI belongs to later UI work; no public token endpoint is specified here. Production should use constant-time comparison.

Bearer Authorization (case-insensitive scheme), including a valid main-owner PAT, is rejected with 403 BEFORE invoking legacy mobile authentication, even with a valid owner cookie. This preserves T047's no-change condition, including token telemetry. Missing/invalid/expired/inactive cookie credentials yield 401; authenticated forbidden role/tenant/mapping and invalid cookie request protection yield 403. Legacy localized auth errors are allowed without credential disclosure. Tests do not pin business error semantics, replay or effects scheduled by later tasks.

## Tests

68 new cases, all orchestrator-written:
- `test_http_router_allows_explicit_main_owner` (10): two independently mapped owner IDs × GET/POST/PUT/PATCH/DELETE. Stale signed role and conflicting query/body selectors cannot replace authenticated identity. Exactly one witness hit; both full DB dumps unchanged. GET has no Origin/CSRF.
- `test_http_router_refuses_roles_tenants_and_unmapped_owner` (8): orders staff, admin staff, full-access reseller owner, and web ID overlapping Telegram owner × read/write. Otherwise valid request protection; staff mappings deliberately match so mapping cannot mask role. HTTP403 and zero changes.
- `test_http_cookie_mutations_require_origin_and_session_csrf` (36): four unsafe methods × absent/foreign/null/wrong-scheme/wrong-port/suffix Origin, absent/wrong/other-session CSRF. Each independently invalidates one factor; spoofed Host/forwarded headers cannot change trusted origin. HTTP403, no changes.
- `test_http_router_requires_valid_session` (6): missing/tampered/expired/inactive session; URL token in cookie or query. HTTP401, no changes.
- `test_http_bearers_rejected_before_any_database_change` (8): independently built valid main-owner PAT or subscription bearer × with/without valid owner cookie × GET/POST. HTTP403; both full DB dumps and witnesses unchanged, including PAT last_used_at.
