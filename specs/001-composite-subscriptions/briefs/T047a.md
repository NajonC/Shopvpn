## Interfaces

Routine Python API decisions for T048, fixed here for executable tests:
- `Principal(identity_domain: str, authenticated_actor_id: int, tenant_installation_id: str, role: str, authenticated_interface: str)`. Server-created identity record; never deserialize it from client JSON. Domains remain separate even for equal numeric IDs.
- `telegram_principal(event, *, tenant_installation_id: str) -> Principal`: called only after authenticated Telegram transport; takes `event.from_user.id` for either message or callback. Missing sender/id raises `AuthorityError("unauthenticated")`. Never falls back to callback data, message actor or client selectors. Uses the trusted installation argument verbatim; returns domain/interface `telegram`, role `customer`. Reseller/discount buyer metadata does not alter that identity.
- `authorize_customer_resource(principal, *, main_installation_id: str, resource_tenant_installation_id: str, customer_telegram_id: int) -> None`: trusted configured main identity and persisted resource owner metadata, never caller selections. Requires Telegram domain/interface, customer role and main-store principal, else `AuthorityError("forbidden")`. Resource tenant and customer must equal the principal's tenant/actor, else opaque `AuthorityError("not_found")`. No effects before refusal.
- `AuthorityError(Exception)` has `.code` and `str(error)` equal to the constant code above; excludes payload/resource/private details.
- These functions are identity/ownership components, not full business-command authorization. Existing shop eligibility, transport authentication, resource lookup/missing-resource handling and command-specific gates remain required at their later integration tasks. No fake eligibility certification here.
