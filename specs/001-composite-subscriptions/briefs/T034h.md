## Rules

1. "For new operation-based handling, `users.test_used` projects fulfilled ordinary consumption and pending reservations remain separate. The existing `database.py:try_reserve_test_slot:2266` increments that same counter before provisioning, so a pre-upgrade value is not proof that every counted attempt fulfilled. Quiesce affected admissions and reconcile known in-flight attempts during upgrade; preserve every prior count, classify demonstrably pending attempts into retained identity-based holds without counting them twice, and hold any unresolved remainder rather than subtracting it or assuming success. Supported prior-schema fixtures must exercise this ambiguity." [data-model §9]

## Owner decisions (2026-11-02)

- A separate step, not part of `migrate`: `migrate` gets no installation id, and the hold rows need one; it comes from the processing-control row, which also shows admissions are paused.
- Proof = delivery rows, one per count: `custom_configs` with `source='test'` and used `test_configs` link-bank rows. Accepted gap: a reset followed by a crashed attempt looks proven by the older row, because reset times are not recorded.
- The holds are `uncertain_hold`, and `users.test_used` stays exactly as it is: the holds are part of that count, not extra. Later shared eligibility must not add these holds to `test_used` again.

## Interface T041 builds (also in the test section's header comment)

`reconcile_legacy_test_usage(main_path, *, crash=None) -> LegacyTestReconciliation`, with `LegacyTestReconciliation(holds)` a frozen dataclass and `holds` a tuple of `(telegram_id, legacy_test_ref)` per row this run created, in creation order.

- Refusals, before any change: a missing main file (never created), or one below `SCHEMA_VERSION`, raises `MigrationError` (not `UnsupportedSchema`); one above it `UnsupportedSchema(path, version)` with the realpath; no `composite_processing_control` row, or `admission_mode` other than `'maintenance'`, `MigrationError`.
- Proofs for Telegram id T: `custom_configs` rows with `user_id = T AND source = 'test'` (only when the table has a `source` column) and `test_configs` rows with `assigned_user_id = T AND is_used = 1` (only when the table exists).
- Each `users` row with `test_used > 0`, in ascending `users.id`: `R = test_used - min(test_used, proofs)`; count k = 1..R has ref `legacy-test-<T>-<k>`. A ref with no `ordinary_test` reservation yet (any state) gets one `resource_reservations` row: new UUID4 `reservation_id`; `resource='ordinary_test'`; that `legacy_test_ref`; the control row's `installation_id`; `customer_telegram_id` T; `sequence` one above the highest existing `sequence` (0 when none); `state='uncertain_hold'`; `transition_key` `legacy-upgrade:<ref>`; `accepted_at = transitioned_at` = one UTC epoch-ms reading per run; every other column NULL.
- One `BEGIN IMMEDIATE` transaction on its own connection (as `migrate`'s members: `isolation_level=None`, `BUSY_TIMEOUT_S`, foreign keys on, `synchronous=FULL`): the rows, `crash("before commit")`, `COMMIT`, `crash("after commit")`. Anything raised before `COMMIT` rolls back and propagates unchanged.
- Nothing else changes in the main file; reseller and FSM files are not touched.
