## Interfaces

These are routine new Python API choices, not additional product policy:

- `SecretError(ValueError)` is a sanitized error boundary; it must not chain an exception containing a secret.
- Frozen dataclass `EncryptedValue(version: int, key_id: str, nonce: bytes, ciphertext: bytes)`.
- `SecretBox(keys: dict[str, bytes], current_key_id: str)` accepts explicitly supplied authorized AES keys, fails on missing active/invalid keys, and never generates fallback keys. Tests use 256-bit keys.
- `SecretBox.encrypt(plaintext: str) -> EncryptedValue`; version 1, active key ID, independently random 12-byte nonce, AES-GCM ciphertext including the 16-byte tag. AAD: `b"shopvpn:secrets:v1:" + key_id.encode("utf-8")`.
- `SecretBox.decrypt(value: EncryptedValue) -> str`; resolve the stored key ID, preserve old-key readability, refuse unsupported versions, absent/wrong keys and corrupted nonce/ciphertext/ID with `SecretError`.
- `token_digest(token: str) -> str`: lowercase 64-character SHA-256 hex of exact UTF-8 input, without normalization.
- `SecretRedactionFilter()` exposes `filter(record: logging.LogRecord) -> bool`. Discard free-text message/arguments, raw exception/traceback/cached exception/stack text and arbitrary extras; preserve severity and safe structured `operation`, `tenant_id`, `record_id` context. This deliberately conservative contract avoids attempting to recognize unknown bare passwords. It does not require a particular placeholder string.
- `install_log_redaction(logger: logging.Logger) -> None`: safe on repeated calls; protect direct records and descendant records handled by that logger's handlers. Future entry points must install it before logging; a filter on an ancestor logger alone does not filter propagated child records.
- `audit.sanitized_diagnostic(*, operation: str, tenant_id: int, record_id: int, error: BaseException | None = None) -> dict`: exactly the supplied operation/tenant_id/record_id, with no error text, secret payload or fabricated completion. Inputs are already trusted structured identifiers, not arbitrary inbound payloads. Actor authorization and orchestration recovery paths belong to later tasks.

## Tests

Already written and staged: `tests/unit/test_secrets_and_audit.py` (22 cases).

1. Independently decrypt wrapper output with real AESGCM; assert version=1, key_id=active, nonce length=12, ciphertext length=UTF-8 length+16; round-trip token, password, URI, subscription URL, empty and Unicode strings; envelope frozen and repr leak-free.
2. Independently construct old-key ciphertext; decrypt with a rotated keyring; new encryption selects active key.
3. Encrypt identical text 64 times: all nonces and ciphertexts distinct.
4. Six isolated refusal cases: absent key, wrong key, flipped ciphertext byte, flipped nonce byte, unsupported version, relabelled key ID even when the alias has the same raw key. Scan exception chains.
5. Three invalid key configurations: empty keyring, absent active ID, 31-byte key. No silent key generation.
6. SHA-256 against independent hashlib for generated values, empty, whitespace-sensitive and Unicode input; known `abc` digest `ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad`.
7. Six redaction surfaces: literal message, positional args, mapping args, live exception traceback, cached exception/stack, nested extras. Scan raw records and formatted output; retain provision/7/19 and ERROR severity.
8. Installed protection: repeated installation emits exactly two safe lines, direct logger and propagated descendant.
9. Diagnostics with and without a secret-bearing error: exactly `{"operation": "provision", "tenant_id": 7, "record_id": 19}`.
