**Schema design (Claude's; T038 builds exactly this):**
- Every id is TEXT, every time an INTEGER of UTC epoch milliseconds. Byte columns are `typeof(x) = 'integer' AND x >= 0`.
- A meter's `traffic_key` is its child's generated email. One observation row carries both directions, so a meter keeps one `last_observation_id`.
- Same-owner rules use composite foreign keys onto these unique keys: `composite_meters (meter_id, subscription_id)`, `composite_children (child_id, physical_panel_id)`, `composite_observations (observation_id, meter_id)`, `composite_entitlement_periods (period_id, grant_kind)`, and a new unique index on `composite_prepared_bindings (binding_id, physical_panel_id)`.
- Carried and forfeited time are milliseconds (`carried_ms`, `forfeited_ms`), so nothing is rounded. The 360-hour cap is 1_296_000_000 ms. `PREVIOUS_EXPIRY` below is `ep-1`'s expiry.
- Reminder `status` is `armed`, `due`, `accepted` or `cancelled`. A reminder period exists only for `initial_paid`, `renewal` and `conversion` grants.

"Accepted" means the statement runs without error. "Single row per case" means: a parametrized test that runs `_chain57(until=<its table>)` and then puts one row of that table with the base values plus the case's changes, so every case runs on a fresh database and needs no new ids.
