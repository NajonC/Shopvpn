# Provider, remote work and accounting contracts

**Proposed optional capabilities**, through existing `get_provider(server)` and `BasePanelProvider`. Existing methods, registered identifiers, `PanelUserResult`, typed errors and `preserve_remaining` remain compatible. Other providers default to explicit `UnsupportedCapability`; no caller makes panel-specific HTTP or selects unsupported composite brand. This contract is provisional where E-001 evidence is missing, including RX-01 under the existing E-001/E-002 provider capability gate. RX-01's detect-and-repair contract ([RD-10](../research.md#rd-10--rx-01-detect-and-repair-with-continuous-reconciliation), owner decisions RX-OWN-001) awaits V-RX-01. Its accounting interface follows approved requirement change PR-002 ([RD-09](../research.md#rd-09--renewal-boundary-attribution-from-saved-starting-readings)).

## Capability manifest and explicit child scope

`CompositeCapabilities {panel/core revisions, API dialect, TLS trust reference, explicit_auth, inactive_create, canonical_lookup, mutation_scope, absolute_update, prior_execution_completion_or_fencing, runtime_confirmation, native_session_policy, meter_authority/topology, observation_validity, decrease_epoch_semantics, collector_cadence, restart_loss_bound, restart_evidence, periodic_reset_absence, counter_retention, strict_node_export, route_namespace_match, shared_restart_conditions}` is versioned and recorded against a **verified physical panel**, not guessed from `panel_type='3xui'` or inbound-list success. Execution safety records mechanism, scope, downstream effects and evidence, not an assumed boolean capability. Absent/contradictory required capability blocks binding/sales. Source research versions are not automatically supported versions. Under PR-002, `meter_authority/topology` is the standalone panel serving the meter; a master/node (multi-node overlay) topology is outside the supported deployment and blocks binding until G-A is re-checked. `restart_loss_bound` records the measured, store-absorbed panel/Xray restart undercount explicitly (FR-034); `restart_evidence` records whether a supported read exposes a restart (optional; unavailable is not a failure); `periodic_reset_absence` records verification that no panel periodic traffic reset applies to composite children (field and scope unverified; E-001). The deployed target is 3x-UI v3.9.0 on standalone panels (owner-reported, with Xray-core v26.9.30); V-GA-01–V-GA-04 established these entries on a lab replica ([GA-MAN-002](../research.md#ga-man-002--v-ga-01v-ga-04-lab-run-2026-10-14)): `collector_cadence` 5 seconds; `restart_loss_bound` at most four collection intervals (20 seconds) per restart, the owner's bound ([GA-OWN-004](../research.md#ga-own-004--restart-loss-bound) D12) over a measured maximum of 13.05 seconds; `restart_evidence` available for Xray restarts through `server/status` `appStats.uptime` and unavailable for panel-only restarts; `decrease_epoch_semantics` confirmed for per-client reset, `updateTraffic`, DB restore, same-email recreate and periodic reset. `periodic_reset_absence` is still verified per child.

Under RD-10 (2026-10-15), three entries change meaning:
- `prior_execution_completion_or_fencing` records the measured execution behavior from V-RX-01(a)/(b). The expected result is no natural bound, because v3.9.0's per-inbound client lock has no timeout. The entry also records the owner-set quarantine.
- `shared_restart_conditions` must show `restartXrayOnClientDisable` off (owner decision RX-D2; 3x-UI default on). This is verified before binding and re-verified by the sweep. A panel reporting it on, or whose setting cannot be read, is blocked from new composite binding and raised as FR-041 drift.
- A new `inbound_client_read` entry records the per-inbound client-list read the continuous sweep uses.

`ChildIntent {operation/subscription/child/generation IDs, physical panel, canonical email/key, explicit auth type+encrypted secret reference/fingerprint, exact inbound attachments, protocol/flow settings, owner-prepared route binding, desired_fields, desired_revision}` is durable before calls. It contains no customer-supplied routing rule. Composite current source HTTP must move to peer verification with configured trusted CA/certificate identity; transport/application failure has typed semantics and sanitized messages. Don't expose token/body/URI excerpts.

Selected child management avoids panel-side automatic reset/renewal and separate commercial allowances. Candidate zero native quota/expiry fields mean manager-controlled finite parent entitlement, not unlimited product. This field binding and disable/runtime behavior must pass capability checks before use. Creation is disabled until complete preparation and legitimate access convergence. No remote generated secret is accepted as replacement for intended persisted authentication. Ordinary renewal never calls generic additive `update_user(reset_usage=True)`.

## Provider operations

| Proposed signature | Meaning and required evidence |
| --- | --- |
| `inspect_child(scope) -> ChildObservation` | Distinguish found_verified, confirmed_absent, owner/generation/attachment mismatch, unsupported, transient and invalid application response. Return actual canonical auth/settings/membership fingerprint. Same name alone is insufficient. Missing object cannot mean zero traffic or permission to adopt/recreate. |
| `prepare_child(intent) -> MutationObservation` | Exact persisted credential and attachment set, inactive state, no shared route/listener/outbound changes. Response may be confirmed, rejected-no-effect or uncertain/partial; reconcile same intent before retry. Current `create_user` internally generated enabled secret is not this operation. |
| `apply_child_state(intent, canonical_observation) -> MutationObservation` | Absolute desired settings using fresh verified canonical field merge and correct full API scope; one coordinated canonical write, not stale per-inbound snapshot loop. Preserve unrelated fields/users. Latest restrictions/revision checked before call and after evidence. |
| `observe_meter(scope) -> MeterObservation` | Strict nonnegative non-boolean upload/down integers for the verified standalone-panel authority/ownership/topology, with dispatch time and Shopvpn receipt time; receipt time is the observation time (PR-002/FR-035). HTTP/application failure, missing object, timeout or malformed counters return an explicit no-observation outcome, never zero. Never calls reset, bulk-reset or update-traffic endpoints. No panel source clock is claimed. |
| `export_node(intent, prepared_descriptor) -> VerifiedNodeDescriptor` | One exact selected protocol endpoint/transport/security/flow/remark; no first-link fallback, extra native addresses, defaults or omission. Return explicit missing-required-field failure. |
| `revoke_child(scope, current_intent) -> MutationObservation` | Deny fresh authentication via supported controls; preserve traffic/identity needed for accounting/cleanup. Delete only after retention/absence/runtime contract known; disable first when it preserves useful evidence. No reset or unapproved shared restart. Terminal revocation under RD-10: disable at once, record final traffic, then delete after the quarantine and a no-growth settle period, batching deletes per panel. With `restartXrayOnClientDisable` off, a successful removal restarts nothing, but a failed runtime removal during delete can still restart Xray (v3.9.0 source; V-RX-01(g)). |
| `observe_inbound_clients(panel, inbound) -> InboundClientsObservation` | One read of an inbound's client list, with Shopvpn receipt time, used by the RD-10 continuous sweep to compare every owned identity's state with desired state and detect reappearing deleted identities. A failed, timed-out or malformed read is `unknown`, never `consistent`. Read-only; never repairs by itself. |
| `confirm_runtime_state(scope, desired) -> RuntimeEvidence` | Positive evidence appropriate to deployed native behavior, backed by controlled fresh-authentication checks. API acceptance or DB desired state alone is not confirmation. If installed panel has no safe runtime proof, fail explicitly and keep pending; E-001 must resolve the supported mechanism before implementation/release claims. |

`MutationObservation {scope, intended_revision, dispatch/request_reference, application_result, affected_attachment_set, observed_db_fields?, runtime_observation?, observed_at, prior_execution_status, completion_or_fencing_evidence?, definite_no_effect?, partial_effects?, uncertainty_reason?}` separates observed state from whether prior work can still execute. Any timed-out request or local failure after dispatch stays uncertain until its RD-10 quarantine ends and a read-back reconciles it. `success:true` cannot alone imply complete provisioning/revocation or gap-free metering. An `UnsupportedCapability` is distinct from transient retryable failure.

Fresh-auth confirmation uses actual native credential authentication, not ping/TCP-open/download/list-removal nor an additional mux stream over an authenticated tunnel. Existing native sessions remain separate recorded exposure. No custom Xray session-kill/core modification or service-wide restart is introduced. Composite panels run with restart-on-disable off (RX-D2). Restart conditions that remain, such as a failed runtime removal during delete, are measured against unrelated users by V-RX-01(f)/(g). Dangerous bulk operations are not selected.

## Physical routing and export

Select versioned anchored authenticated-email namespace matching owner-prepared route rules, one child canonical email per intended route/opaque identity. Lifecycle retains intended routing identity across renewal; leak/equivalent moves generate fresh identities in the appropriate prepared namespace. The owner supplies listener/inbound/outbound policy, route precedence and supported regex/core settings. Shopvpn validates selected binding and actual egress in controlled checks, never generates or edits shared configuration.

Six-node descriptor fields are exhaustive by protocol:

- VLESS REALITY: UUID, exact endpoint/443, encryption, required flow, transport, server name, public key, short ID, supported fingerprint and any required path field.
- VLESS WS-CDN: UUID, intended CDN endpoint/port, TLS/SNI/fingerprint where configured, Host/path and transport options.
- Trojan gRPC: protocol password, endpoint/port, security/SNI, serviceName and any mode/authority fields required by prepared settings.
- VMess TCP-TLS: UUID, security/alterId as configured, endpoint/port, TCP/header settings, TLS/SNI and owner remark.

Normalize exact fields into provider-local descriptor, preserve them in strict URI encoding and verify exported authentication matches canonical intended credential. No extra public A listener/L4/outbound clone; five live choices and six acceptance nodes remain distinct. Public source suggests feasibility but actual version-specific flow mutation/route precedence is unverified.

## Remote execution and fencing

Bot/admin/payment processes persist intent only for composite side effects. Worker holds main singleton OS lock; provider writes use physical-panel OS lock and durable uncertain-scope marker across affected Shopvpn callers. Reconciliation reads may run with bounded concurrency; writes on a panel serialize conservatively until narrower safe scope is proved. Main-thread locks/DB leases are not remote fencing. After a timeout or process death, the request becomes uncertain and the RD-10 quarantine applies to its client. The quarantine widens to the inbound if V-RX-01(c) shows lost updates between clients of one inbound. Shopvpn's own writes on a physical panel stay serialized across aliases, canonical identities/attachments and affected legacy writers. Other independent panels, safe reads, local settlement and protective-intent acceptance continue.

**RX-01 contract — detect-and-repair ([RD-10](../research.md#rd-10--rx-01-detect-and-repair-with-continuous-reconciliation); owner decisions RX-OWN-001, 2026-10-15).** It replaces the original predicate below for composite mutations, because inspected v3.9.0 supplies no completion, fencing, drain or execution-bound mechanism.

1. **Absolute writes.** Every write carries the client's complete desired state.
2. **Direction rule.**
   - A changed access-reducing state is dispatched immediately, never behind a quarantine.
   - A retry of the same state waits for the uncertain request's quarantine (Q, owner-set) and a reconciling read-back.
   - An access-restoring change after an uncertain access-reducing request waits for that request's quarantine (configurable restore wait).
3. **Confirmation.** "Confirmed" requires:
   - no uncertain request for the client still in quarantine;
   - a read-back after the latest write matching the desired state;
   - runtime fresh-authentication evidence where required (`confirm_runtime_state`).
4. **Continuous sweep.** A sweep using `observe_inbound_clients` every S seconds compares every owned identity with its desired state, repairs and records divergences, and treats failed reads as unknown.
5. **Repeated divergence.** N divergences within W open an FR-041 discrepancy. Access-reducing repairs continue; access-restoring repairs pause.
6. **Repair failures and stalls.** A repair that times out is uncertain under item 2's quarantine rule and escalates after R failures. A panel whose writes repeatedly fail to complete within T raises a panel-stall escalation.
7. **Panel-only restart.** Restarting a stalled panel automatically awaits RX-D3.

This contract accepts that a late request can temporarily reverse an accepted access state until a later sweep repairs it, normally within one sweep interval and longer while a panel is stalled (approved PR-003). Writing it supplies no measured values and does not pass the gate; V-RX-01 must.

*Original predicate (2026-10-06), retained as history:* Clear the relevant barrier only with (1) evidence that every prior conflicting request and its downstream work has completed, been fenced, been drained, or otherwise cannot later invalidate current required state; (2) fresh verified ownership and current DB/runtime evidence; and (3) revalidation of the latest applicable intent before a subsequent mutation/retry or completion claim. Read-back, even with successful runtime probes, establishes only an observation. Elapsed time, client timeout, local lock release, revision/restore-epoch checks or a guessed quiet period are insufficient. A bounded wait is valid only where an evidenced execution bound or other validated mechanism excludes late effects. `confirmed_absent` alone is not safe-to-retry. Retain `execution_hold`/manual recovery if proof is unavailable. The existing E-001/E-002 provider capability gate now records RX-01 explicitly; writing this predicate supplies no working provider mechanism and does not pass that gate.

Worker claim/ack predicates include installation/restore epoch, operation identity, child generation and current desired revision. Obsolete results are recorded, not acknowledged as current success. Reconcile late conflicting enable/disable to the current absolute state through the quarantine read-back and continuous sweep, and verify it before reporting completion. Nothing local can stop an already-dispatched remote effect, so record the divergence and exposure, repair it, and escalate repeated or unrepaired cases. The capability check fails if V-RX-01 shows the detect-and-repair contract cannot hold. Pending cancellation during authorized renewal is a funding block, not a competing revocation intent; access still follows existing terms/independent restrictions. Final cancellation and accepted leak revocation cannot be overwritten; successfully renewed eligible terms must also escape obsolete old-term cutoff. Protective acceptance does not wait for remote locks. Deadlines, final-stage start and escalation remain original even during a quarantine or panel stall; record missed targets, retain cleanup and settle otherwise processable refunds independently.

10-second total call timeout is the initial proposed setting, with finite retry policy and urgent scheduling from plan; measure before release. Rejected-no-effect can retry if still eligible and rejection proves no remaining execution. Unknown results wait for their RD-10 quarantine and a reconciling read-back first; definite no-effect failures use the bounded backoff. Retry exhaustion leaves cleanup/refund/remote obligations and owner action, never a completed flag or local removal. Partial compensation/refund is not global rollback; refund can settle even while revoke remains uncertain.

## Accounting interface — PR-002 contract; G-A closed

Proposed `ingest_observation(meter_id, evidence) -> AccountingResult` transaction validates physical owner/directions/epochs, inserts once, advances observation time only for an accepted response newer than the latest accepted one, generates per-direction deltas, opens a new epoch with a gap on any decrease (no negative delta) and retains period allocation evidence. Return confirmed uncapped lifetime use, current period allocation, remaining qualified allowance, oldest required observation time, freshness/gaps/restart-loss annotations/serving-versus-retired exposure and desired enforcement trigger. Duplicate/alias/out-of-order responses never create new consumption or advance observation time.

Proposed `establish_period_boundary(subscription, operation, readings) -> BoundaryResult` runs inside the main-database transaction that makes renewal/conversion effective (RD-02), after all-child readiness, without deliberately interrupting usable old service and without any remote mutation. Immediately before the commit the worker re-reads every required meter through `observe_meter`; the transaction saves, for every owned meter and direction, its latest accepted observation as the immutable boundary starting reading (epoch, observation ID, value, receipt time). Every current-serving required meter's reading must be at most 60 seconds old at commit; otherwise return `pending_stale_reading` and leave renewal pending inside its original window (FR-046/FR-047). The result records `A_old`, `U_old` (confirmed deltas through the readings), `O = max(U_old − A_old, 0)`, eligible `C`, `A_new`, `N = A_new + C` and resulting expiry. Because ingestion and the commit serialize on the main-database writer, the boundary falls on a chain node and no delta spans it; usage first reported after it is new-period (PR-002/FR-045). A retired meter whose latest reading is older than 60 seconds has its first later delta marked old-period store-absorbed FR-066 exposure. The commit is keyed by the renewal operation: a repeated call returns the existing period and readings, and after an indeterminate commit the key is queried before retry. No interval is split at commit or HTTP time. Panel resets are never called; a decrease near the boundary is handled as a gap in whichever period contains it.

The inspected cumulative traffic GET has no panel-side measurement clock or atomic cut; approved PR-002 accepts Shopvpn receipt time of valid responses and reporting-order attribution instead, so receipt time is the defined observation time, not a substitute for a missing clock. Controlled known-byte V-GA-01–V-GA-04 checks on a lab replica of the deployed 3x-UI v3.9.0 standalone panels ([quickstart](../quickstart.md#focused-correction-scenarios--proposed-not-run), [GA-MAN-002](../research.md#ga-man-002--v-ga-01v-ga-04-lab-run-2026-10-14)) confirmed collector cadence, the restart loss bound (D12), decrease semantics and boundary behavior, so these interfaces' dependent implementations may proceed, subject to RX-01 for remote mutations; V-GA-05/V-GA-06 verify the implementation before release; no direct core API bypass, new custom core or generic per-renewal owner intervention is authorized. A failed check is reported for explicit resolution of affected FR-034–FR-046/SC-003–SC-005. Meter tables and mocks cannot resolve it.

Fresh verified display requires every current-serving meter's observation age (since Shopvpn receipt) ≤60 seconds and reconciled/explicitly settled history. Known invalidity warns immediately. Any last-trustworthy required meter reaches grace at five minutes across restart; exhaustion/expiry acts earlier. Explicit emergency cutover may retire old meters from current grace, while unknown exposure/late use/cleanup remains. Known allowance exhaustion uses exact bytes; cutoff budget includes panel internal measurement lag, worker detection, queue, action and runtime confirmation within60seconds normally. No finite outage excess or forced existing-session promise is added.
